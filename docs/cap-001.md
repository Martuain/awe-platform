# CAP-001 — Business Discovery

## Objective

Turn a user's natural-language description of a business into a structured,
reviewable and versioned `DiscoveryContext` that downstream AWE capabilities
can consume only after explicit human approval.

## Current vertical slice

The current implementation supports:

1. Create a project.
2. Start Business Discovery.
3. Add conversational messages.
4. Extract deterministic business knowledge.
5. Track completeness and open questions.
6. Move the context to `awaiting_approval` when the minimum baseline is met.
7. Review the structured context in AWE Studio.
8. Approve the context.
9. Prevent mutation after approval.
10. Persist context versions through the repository abstraction and PostgreSQL
    implementation when `DATABASE_URL` is configured.

## API

- `POST /api/v1/projects`
- `POST /api/v1/business-discovery/start?project_id={id}`
- `POST /api/v1/business-discovery/message`
- `GET /api/v1/business-discovery/context/{project_id}`
- `POST /api/v1/business-discovery/approve/{project_id}`

## Knowledge contract

The initial `BusinessKnowledge` model contains:

- business name;
- industry;
- goals;
- audience;
- value proposition.

Each extracted field can carry confidence and source provenance.

## Current evaluation rule

The development baseline considers Discovery complete when both industry and
at least one goal have been captured. This is deliberately deterministic and
should be replaced/extended by a proper capability evaluator before CAP-001 is
considered production-ready.

## Product principle

AWE must not silently turn inferred business assumptions into authoritative
requirements. The Discovery context becomes authoritative only after human
approval.

## Remaining CAP-001 work

- replace the keyword-based mock extractor with a provider-agnostic structured
  model gateway;
- implement explicit Discovery evaluation dimensions and findings;
- improve conversational question generation instead of using a single fixed
  open question;
- capture audience and value proposition as first-class discovery targets;
- expose provenance and confidence clearly in Studio;
- add richer API/integration tests for revision/version semantics;
- validate PostgreSQL persistence in CI;
- add an end-to-end browser test for the Studio experience;
- define the production model-provider adapter behind the gateway.

## Validation baseline

The repository currently validates with:

```text
pnpm lint   -> successful
pnpm build  -> successful
pnpm test   -> successful
```

The Studio now provides the first user-facing CAP-001 flow and communicates
with the API through `NEXT_PUBLIC_API_URL`.
