# AWE Engineering Constitution

## 1. Knowledge First
Structured project knowledge is the primary product asset. Generated code, prompts, documents and websites are downstream artifacts.

## 2. Capability Driven
Capabilities are the stable business-facing execution boundary. AI agents/roles/models are replaceable implementation mechanisms.

## 3. API First
Capabilities are specified by machine-readable contracts before UI integration.

## 4. Human Approval
Publishable artifacts require explicit human approval in the MVP.

## 5. Model Agnostic
No capability may depend directly on a specific model vendor. Model access occurs through an abstraction boundary.

## 6. Evaluation Is a First-Class Concern
AI outputs must be evaluated against explicit criteria before they can progress to publication.

## 7. Open-Source First
Prefer mature open-source technologies and open standards. Every infrastructure dependency should have a replacement/self-hosting strategy where practical.

## 8. Traceability
Requirements, implementation tasks, tests and decisions must be traceable.

## 9. Simplicity Before Scale
Do not introduce distributed systems, graph databases, workflow engines or additional infrastructure until an observed requirement justifies them.

## 10. AWE Is Its Own First Customer
The platform should eventually be capable of generating and maintaining its own project artifacts, while the bootstrap remains manually controlled until that capability is proven.
